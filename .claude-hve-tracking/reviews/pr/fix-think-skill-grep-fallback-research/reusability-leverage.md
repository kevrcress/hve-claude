## Reusability and Leverage

### RL-001 [Minor]
Location: `.claude/commands/hve-plan.md:49`, `.claude/commands/hve.md:85` (cf. established precedent `.claude/commands/hve-review.md:129`)
Finding: The PR description states the `/think` fix "deliberately mirrors the already-fixed precedent phrasing" at `hve-review.md:129`, but the actual wording diverges from that precedent rather than reusing it verbatim. The precedent reads: "use extended reasoning to think through severity weights and cross-dimension conflicts before writing the final verdict block." The two new instances instead read: "begin/perform an extended reasoning pass (interleaved/extended thinking) on task complexity, risk surface, and phase ordering before…" This introduces a new sentence template ("an extended reasoning pass") and a new parenthetical alias, "(interleaved/extended thinking)", that appears nowhere else in the repo — not in CLAUDE.md, not in the precedent, not in `.claude/prompts/rpi.md:9` (which uses the plain, already-established term "extended reasoning"). The repo now carries two stylistically different phrasings for the same underlying instruction (do an extended-reasoning pass before this phase's output), and the new parenthetical is an unglossaried technical alias that a future reader/maintainer has no established referent for.
Recommendation: Reuse the precedent's exact clause structure ("use extended reasoning to think through X before Y") in both new locations instead of the new "extended reasoning pass (interleaved/extended thinking)" phrasing, or, if the parenthetical is intentional and needed, add it once to the precedent at `hve-review.md:129` too so all three occurrences share one canonical form.

### RL-002 [Minor]
Location: `.claude/agents/hve-researcher.md:30`, `.claude/commands/hve-research.md:47`
Finding: The two Grep-fallback clauses are described as "near-identical," and mostly are, but they restate the identical sub-rule ("don't use Bash to work around a missing Grep tool") with two different phrasings: "do not reach for Bash to work around this" (agents/hve-researcher.md) vs. "never add Bash to route around this" (commands/hve-research.md). There is no established prior wording for this pattern in the repo (confirmed — no other "fall back"/"fallback" hits for tool unavailability), so this PR is establishing the pattern rather than reusing one, which makes wording consistency between its own two instances the only available reuse signal. Since 13 other files reference Grep and were deliberately left out of scope, this pair of clauses is the template future fixes will likely copy from; letting the two seed instances drift on the identical sub-clause risks a third, fourth, and fifth variant appearing as more carriers are fixed later.
Recommendation: Make the Bash-avoidance sub-clause byte-for-byte identical in both files (pick one of the two wordings), and keep only the parts that legitimately must vary per carrier (e.g., "this agent" vs. "the research phase", and the optional "(broad filename/pattern matching)" annotation). Optionally, note in a comment or the plan artifact that this exact sentence is the canonical template for any future Grep-fallback additions to the other 13 files, so leverage is explicit rather than left to be rediscovered.
