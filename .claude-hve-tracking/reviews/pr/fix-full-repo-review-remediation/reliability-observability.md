## Reliability and Observability

### RO-001 [MAJOR]
Location: `.claude/commands/hve-pr-review.md:22,90-98,162-163` (new "coverage floor" / "Reviewer set" / unconditional Block-rule text); contract at `.claude/agents/hve-pr-reviewer.md:109`
Finding: This PR adds a load-bearing reliability guarantee — "Security coverage is a floor, not a filter" (`CLAUDE.md:299`) and the corresponding unconditional rule in `hve-pr-review.md:162`: "🚫 Block — security Critical or data integrity risk. This rule is unconditional: the Security and Compliance reviewer runs on every invocation." The guarantee is stated as if dispatch always succeeds, but `hve-pr-reviewer.md:109` gives every dispatched reviewer subagent, including the Security and Compliance one, a `Status: Complete | Blocked: [summary]` contract. `hve-pr-review.md` never once mentions "Blocked" (confirmed by full-file search) — Phase 2 ("Wait for all subagents to complete") and Phase 3 ("Consolidate all findings…Tally…Determine overall verdict") give no instruction for what happens when the dispatched security reviewer returns `Blocked` (e.g. its diff.patch is unreadable, or it cannot write its output file). A Blocked security reviewer produces no findings, so nothing distinguishes "security ran and found nothing" from "security did not run," and the new `Coverage:` line (`hve-pr-review.md:54,158`) would have no signal to report the omission honestly. This lets a PR with an unreviewed security-Critical issue read as ✅ Approve — the exact failure mode DEFECT 1/3 (the reason this floor was added) targeted, just triggered by subagent failure instead of `--dimension` filtering.
Recommendation: Add an explicit branch to Phase 3: if the Security and Compliance reviewer's response is `Blocked` or its output file is missing/unreadable, the run cannot produce a verdict better than 🚫 Block (or an explicit "verdict withheld — security dispatch failed") and the `Coverage:` line must record `Security and Compliance: not covered (dispatch failed)` rather than treating it as covered.

### RO-002 [MINOR]
Location: `.claude/commands/hve-pr-review.md:44`
Finding: "Resume semantics" re-runs "only the dimensions whose sections are missing or empty," treating any non-empty section as complete. A dimension whose subagent returned `Blocked` on a prior run may still have written a non-empty section (a heading plus a `Blocked: [reason]` note, or partial findings before the halt); resume would then skip re-dispatching it, silently perpetuating the gap across repeated resumes. The changes log itself flags this exact scenario in Phase 3's "Issues Encountered" ("Resume path noted, not changed") but the shipped instruction text was never updated to distinguish "non-empty because complete" from "non-empty because it failed partway."
Recommendation: Change the resume predicate from "missing or empty" to "missing, empty, or marked incomplete/Blocked," and require the reviewer subagent's own output file to carry an explicit completion marker resume can check.

### RO-003 [MINOR]
Location: `.claude/commands/hve-implement.md:115`
Finding: The step that verifies each `hve-phase-implementor` subagent's work was rewritten from "Read the changes log — verify the subagent updated it correctly" to "Read ONLY the `### Phase N:` section this subagent just wrote… Do not re-read the sections earlier phases own… re-reading all of them per phase is O(N²)." This is a deliberate, documented performance trade-off (Phase 5, `full-repo-review-remediation-changes.md`), but it removes the one built-in cross-phase consistency check that ran during implementation itself. If a parallel-dispatch violation of the `Concurrent Changes-Log Writes` ownership rule (`CLAUDE.md:313`) corrupts an earlier phase's section — the exact failure that rule exists to prevent — nothing in `/hve-implement` will notice until the separate `/hve-review` phase's record-consistency scan runs, which may be a different session entirely.
Recommendation: At minimum, note in Phase 3 (Consolidation) an instruction to re-read the full changes log once, at the end, as a cheap O(N) closing check before marking the log `Complete` — cheaper than the O(N²) pattern this change removed, but still catches cross-phase corruption before handoff to `/hve-review`.
