## Executive Summary

This branch closes 39 findings from the 2026-08-10 full-repo review plus 3 resume-verification
defects, across eleven planned phases. The core engineering is sound: the deduplication sweep
(five duplicated blocks collapsed to one carrier each), the new drift tests 14 and 15, the
security-coverage floor, and the O(N²) read elimination in `/hve-implement` are all correctly
implemented and independently verified. Both test suites pass at 100% (drift 249/249, install
69/69), matching the commit message's claimed 211→249 and 48→69 exactly.

The findings below are almost entirely documentation-and-consistency defects, not runtime bugs.
That is also what makes them worth fixing: six Major findings are precisely the class of defect
this PR existed to eliminate. Two of them are self-referential — the changes log violates
CLAUDE.md's own Corrections protocol, and the PR's deduplication phase created seven new
unguarded copies of the credential list while its own drift corpus was never extended to cover
them.

No Critical findings. No secrets, no committed credentials, no new dependencies, no shell-safety
regressions.

## Findings by Dimension

### Major

#### FC-002 [MAJOR] — `/hve-plan` documents a parallel-validation path that does not exist
`.claude/commands/hve-plan.md:41` describes a Complex plan as "full planning with parallel
validation", and `CLAUDE.md:44` / `README.md:124` both newly claim `--mode full` "uses parallel
validation". `.claude/commands/hve-plan.md:131` dispatches exactly one `hve-plan-validator`, for
every mode: "For **standard** and **complex** plans: spawn one `hve-plan-validator` subagent."
No parallel path exists anywhere in the file. The command file contradicts itself, and this PR
propagated the false claim into two more documents.
Fix: implement the parallel path, or reword all three sites to describe the single validator.

#### RO-001 [MAJOR] — No `Blocked` handling defeats the security-coverage floor
`.claude/agents/hve-pr-reviewer.md:109` defines the subagent contract as
`Status: Complete` | `Blocked: [summary]`. `.claude/commands/hve-pr-review.md` contains zero
occurrences of "Blocked". Phase 3 step 4 fills the `Coverage:` line from the reviewer set
"actually dispatched", and step 5 calls the Block rule "unconditional: the Security and
Compliance reviewer runs on every invocation" — but nothing verifies it *returned*. A security
reviewer that blocks contributes zero findings, is still recorded as covered, and the run reads
as ✅ Approve. This hole sits directly under the coverage floor that is this PR's headline
security feature.
Fix: treat a `Blocked` reviewer as not-covered; never emit Approve when the security reviewer
did not return.

#### RL-004 / DA-002 [MAJOR] — Deduplication phase created 7 unguarded copies of the credential list
*Found independently by the Reusability and Design reviewers.*
The six credential patterns appear literally in 10 surfaces. `canonical_block_corpus()`
(`tests/run-drift-tests.sh:582-589`) walks only `.claude/commands`, `.claude/agents`,
`.claude/prompts`, and `CLAUDE.md` — verified. Guarded: `install.sh`'s `add_ignore` calls (install
test 6) and the repo `.gitignore` (drift test 4). Unguarded: `README.md:44,247`,
`docs/installation.md:26,93,158,195`, and `install.sh:268-274`'s global-mode echo block — seven
copies, none cross-checked against anything. Phase 5 collapsed duplication in `.claude/`; Phase 11
then reintroduced it in `docs/` and `README.md`, outside the corpus the same PR built.
Fix: extend the drift corpus to `README.md`/`docs/`, or derive the echo block from the same list
`add_ignore` uses.

#### II-001 [MAJOR] — Changes log self-contradicts, violating CLAUDE.md's own Corrections protocol
`.claude-hve-tracking/changes/2026-08-15/full-repo-review-remediation-changes.md:997` ("Open Items
Carried to Review") states `*.pfx` was "deliberately NOT added" and "All three lists agree on the
current five". The "Post-Review Remediation" section at line 932 reverses exactly that, and the
on-disk files confirm the reversal (`CLAUDE.md:295`, `install.sh:251,274`,
`tests/run-drift-tests.sh:291` all list `*.pfx`). The stale claim carries no
`(superseded — see Correction 2026-08-15)` annotation, and because it appears *after* the section
that reverses it, a reader encounters the false statement last. CLAUDE.md's `Corrections in
Tracking Artifacts` section states: "A changes log that contradicts itself without correction
annotations cannot be graded ✅ Complete in review." It was graded ✅ Complete.
Fix: annotate line 997's DD-008 bullet as superseded and point to the Post-Review section.

#### DO-003 [MAJOR] — The PR's primary regression gate is undocumented for contributors
`CONTRIBUTING.md:24` still reads "Covers 7 `install.sh` scenarios"; Phase 1's new
`test6_gitignore_credentials` makes it 8. More significantly, `CONTRIBUTING.md` never mentions
`tests/run-drift-tests.sh` at all — the 249-assertion suite every phase of this remediation was
verified against, in the one document whose purpose is telling contributors how to test locally.
A contributor following it would never learn the drift suite exists.
Fix: correct the count to 8 and add a drift-suite section.

#### DO-002 / FC-003 [MAJOR] — README overstates `--subagent-model`'s scope
*Found independently by the Documentation and Functional Correctness reviewers.*
`README.md:139-146` introduces "Flags every dispatching command accepts", stating the two flags
"work the same way everywhere". The `--friction-log` row scopes itself to six named commands; the
`--subagent-model` row carries no scoping. The two sets are genuinely different: `--subagent-model`
also covers `/hve-doc-ops` and `/hve-prompt-builder`, while `--friction-log` covers `/hve-challenge`,
which has no Agent tool (`.claude/commands/hve-challenge.md:4`: `allowed-tools: Read, Write, Edit,
Glob, Grep`). The subsection sits directly beneath a table listing `/hve-challenge` and
`/hve-memory`, neither of which accepts `--subagent-model` — passing it there is silently ignored.
Fix: scope the `--subagent-model` row explicitly and drop the "everywhere" framing.
