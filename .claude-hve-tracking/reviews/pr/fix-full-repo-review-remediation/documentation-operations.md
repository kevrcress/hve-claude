### DO-001 [MAJOR]
Location: `.claude/commands/hve-research.md:20` vs `.claude/commands/hve-research.md:38`
Finding: The file now contradicts itself on how many subagents `--mode` dispatches. Line 20 (Inputs section, untouched by this PR's diff) reads: "`--mode` overrides the difficulty assessment when explicitly passed (`lightweight` = 1 subagent, `standard` = 2–3, `full` = 3–5)." Line 38 (added by this PR's Phase 8/PS-01 work) reads: "When `--mode` was passed, its own cap applies instead: `lightweight` 1, `standard` 3, `full` 5." The first describes ranges (`standard` 2–3, `full` 3–5); the second describes single hard caps (`standard` 3, `full` 5) and explicitly calls itself "not a suggestion." CLAUDE.md:43 and README.md:123 both now echo the line-38 phrasing verbatim ("`standard` 3, `full` 5"), so the command file's own Inputs section is the one stale holdout contradicting the doc set it is supposed to be the source for. This is exactly the kind of self-contradiction Phase 6/RL-01 of this same remediation set out to eliminate elsewhere in this repo.
Recommendation: Reword line 20 to match the binding-cap language at line 38, e.g. "`lightweight` caps at 1 subagent, `standard` at 3, `full` at 5" — or simply delete the redundant Inputs-section parenthetical and point at the Phase 0 table.

### DO-002 [MAJOR]
Location: `README.md:139-146`
Finding: The new "Flags every dispatching command accepts" subsection (added in this PR's Post-Review Remediation item 3) claims both `--subagent-model` and `--friction-log` "work the same way everywhere" among dispatching commands, then lists `--subagent-model <sonnet|opus|haiku>` with no command scoping. This is false: `--subagent-model` is accepted only by commands with the Agent tool and a matching `argument-hint` entry — `/hve`, `/hve-research`, `/hve-plan`, `/hve-implement`, `/hve-review`, `/hve-pr-review`, `/hve-doc-ops`, `/hve-prompt-builder` (verified via each file's frontmatter `argument-hint:`/`allowed-tools:` lines). `/hve-challenge` (`.claude/commands/hve-challenge.md:3-4`, no Agent tool, no `--subagent-model` in argument-hint) and `/hve-memory` (`.claude/commands/hve-memory.md:3-4`, `allowed-tools: Read, Write, Glob`) do not accept it — passing it would be silently ignored, contradicting the row's claim it "[o]verrides each subagent's frontmatter model for one run." The subsection sits directly under the Utility commands table, which lists `/hve-challenge` and `/hve-memory`, so a reader has every reason to assume the flag applies to them too. The `--friction-log` row correctly scopes itself with an explicit command list; the `--subagent-model` row does not, and the two flags do not share the same command set (`--subagent-model`'s set also includes `/hve-doc-ops` and `/hve-prompt-builder`, which do not accept `--friction-log`).
Recommendation: Scope the `--subagent-model` row the same way the `--friction-log` row is scoped, e.g. "Accepted by every command with Agent-tool dispatch: `/hve`, `/hve-research`, `/hve-plan`, `/hve-implement`, `/hve-review`, `/hve-pr-review`, `/hve-doc-ops`, `/hve-prompt-builder`." Reword the subsection header away from "every dispatching command" since no single set of commands accepts both flags.
